# Celestial

小型AI群(ワーカー)と、それを束ねる管理AIで、さまざまな仕事をこの PC の中だけで処理するソフトです。
使うほど速く・正確に・省エネになり、自分専用のAIを学習して育てることもできます。
Android アプリから、会話の続き・PC の遠隔操作・ファイルのやり取りができ、スマホの中のAIだけでも動きます。

- PC 側のコアは Python 標準ライブラリだけで動きます(AI は Ollama)。
- スマホとは Tailscale のアドレスで直接つながり、外部のサーバーを経由しません。

## はじめかた

### PC

1. [Ollama](https://ollama.com) を入れ、モデルを入れます(例: `ollama pull gemma3:4b`、`ollama pull qwen2.5:1.5b`)。
2. [Celestial.cmd](Celestial.cmd) をダブルクリックします。初回は自動でセットアップし、専用のウィンドウで画面が開きます。

入れておくと使える機能が増えるモデル:

| モデル | 用途 |
| --- | --- |
| `gemma3:4b` | 画像の読み取り(添付画像・画面を見る道具)。計測で最も正確なことが多い |
| `qwen2.5:1.5b` | 速い下書き役。自信のない回答だけ、より正確なAIが答え直す |
| `bge-m3` | 言い回しが違っても、同じ趣旨の過去の良い回答を手本にする |

### スマホ(Android)

1. PC とスマホの両方で Tailscale にログインしておきます。
2. PC の画面の「スマホ連携」を開くと、QR コードと6桁の番号が出ます。
3. スマホのカメラで QR コードを読み取り、開いたページの「アプリをダウンロード」でアプリを入れます(初回のみ)。
4. 同じページの「Celestial アプリで接続する」を押すと登録が終わります。アプリの「設定」→「PC と接続」で、アドレスと番号を手で入れることもできます。

- 番号は10分間・1回だけ有効です。8回まちがえると無効になります。
- 初めてスマホからの接続を受け付けるとき、Windows のファイアウォールの確認が出ることがあります。Tailscale のネットワークからの接続を許可してください。
- 登録した端末は「スマホ連携」の一覧から名前の変更・登録の取り消しができます。

## できること

### 会話(PC・スマホ共通)

- PC の画面は、上の帯で「会話・見る・自動化・知識ベース・判断・スマホ連携・学習状況・精度の計測・モデルと設定」を切り替えます。会話の一覧は左に引き出して使い、会話の見出しの左のボタンでしまうと会話が広くなります(しまったかどうかは覚えます。スマホくらいの幅では、会話の上に重ねて出します)。
- 依頼に合った担当(一般・コード・計算と推論・要約・翻訳・文章作成・抽出)へ振り分け、実績の良いAIが答えます。
- 長く複合的な依頼は、管理AIが分解して複数のAIに分担させ、結果をまとめます。
- 画像を添付して質問できます(画像を扱えるモデルが自動で選ばれます)。
- 文字のファイル(テキスト・Markdown・CSV・JSON・プログラムなど)を添付して、要約や質問ができます。
- 会話の流れを踏まえて答えます(「それを英語にして」などの続きの依頼)。
- 回答の「もう一度」で、キャッシュを使わず検証つきで答え直します。自分の依頼は「直して送る」で入力欄に戻せます。
- 回答の「保存」で、Word・Excel(表を含む回答)・PowerPoint のファイルにできます。会話の見出しの「MD書き出し」「Word書き出し」で会話全体の保存もでき、スマホではダウンロードフォルダに保存します。
- 最初のやり取りのあと、会話に内容を表す短い題名を AI が付けます(例:「4月の店舗別の売上を表にまとめて。東京 1,2…」→「店舗別売上表」)。読み込み済みのAIを使うので 0.1〜0.5秒で済み、自分で付けた題名は変えません。
- 「良い」「悪い」の評価を付けると、手本の記憶・モデル選び・キャッシュにすぐ反映されます。
- 会話は PC とスマホの間で同期されます。スマホで始めた会話を PC で続けることも、その逆もできます。
- **あなたに合わせる**: 設定の「AIへの指示」(答え方の好みなど)と「覚えていること」を、PC とスマホのすべての会話で使います。会話で「覚えて: 〜」「〜と覚えておいて」「これから〜と記憶して」など自然な言い回しで頼むと覚え、「忘れて: 〜」「〜を忘却して」で消え、「何を覚えてる?」「メモリの一覧」で一覧が出ます(AIを呼ばずに即答)。エージェントモードでは `save_memory` 道具でも保存できます。指示を変えると、それより前に作った回答はキャッシュから使いません。
- **今日の日付**: 日付や時刻が関わる依頼(「今日は何曜日?」「大晦日まであと何日?」など)には、今日の日時を渡します。小さいAIは日付の計算を誤るので、日数・曜日・「100日後」などはプログラムで計算した値を渡し、短い日付の質問には計算した値でそのまま答えます。こうした依頼はキャッシュを使いません。
- **最新のニュース**: 「ニュース」「最新」などを求められたとき、ネットの利用を許可していれば、公開されている見出し(RSS)を取得して、それだけをもとに要約し、媒体名・日付・出典を付けます。許可していないときは、最新の情報は取得できないと最初に伝えます(小さいAIは、学習した古い知識から「最新ニュース」を作り上げてしまうため。実際にスマホからの依頼で起きたので直しました)。こうした依頼はキャッシュを使いません。
  - 話題を読み取って、取ってくる先を変えます。話題なし(「今日のニュース」)は NHK・BBC の主なニュース、分野(「経済ニュース」「海外のニュース」「tech news」)は NHK・BBC のその分野、ほかの話題(「AIに関する最新ニュース」「大谷翔平の最新ニュース」「AIや半導体のニュース」)は Google ニュースの検索で直近1週間を探します。見つからなければ、そう伝えます。
  - 検索の結果には迷惑な記事が混ざります(「AI」の検索では、見えない文字と埋め込み前の型が残った成人向けの宣伝が、1つの媒体から99件中75件来ました)。そうした見出し・広告・株価のページを除き、1つの媒体は3件までにして、検索の関連の強い順に選んでから新しい順に並べます。スマホから実際に来た「aiに関する最新ニュースをたくさん取得し、要約して」で、エヌビディアの CEO 辞任・Microsoft の障害・Sakana AI の上場計画・米国の AI 規制法案などの11件を、4秒ほどで要約できることを確かめました。
- **覚えますか**: 発言に利用者自身についての事実(好み・習慣・仕事・予定など)があると、判断の機能(下の「判断」)で見分けて、回答の下に「覚えますか: 私は花粉症で春が苦手。」のように提案します。押すと覚えます。8件の確認では、本人の話の5件中3件で提案し、本人の話でない3件には出しませんでした。

### 知識ベース(ローカル RAG)

画面の「知識ベース」タブ、エージェントの道具(`kb_search`・`kb_add`)、自動化の「知識ベース検索」、CLI(`celestial kb`)から、この PC に資料を蓄えて検索できます([knowledge.py](src/celestial/knowledge.py))。

- **取り込める資料**: メモ、テキスト・Markdown・CSV・JSON・ソースコード、Word(`.docx`)・Excel(`.xlsx`)・PowerPoint(`.pptx`)・PDF(`.pdf`)、フォルダ一括取り込み、公開 Web ページの URL。
- **ハイブリッド検索**: 文字 n-gram・語句一致・完全一致の語彙検索と、埋め込みモデル(`bge-m3` 等)による意味検索を RRF(Reciprocal Rank Fusion)で統合して関連箇所を取り出します。
- **会話での自動参照**: 質問に関係のある資料が登録されていれば、上位の抜粋と出典名を自動でプロンプトに添えて回答します(設定で自動挿入のオン・オフも可能です)。

### 自動化(n8n のようなワークフロー)

画面の「自動化」で、きっかけと手順をつないで仕事を自動で動かします([flows.py](src/celestial/flows.py))。

| きっかけ | 手順 |
| --- | --- |
| 手動(PC・スマホから)、決まった時刻(曜日つき)、一定の間隔、Webhook(鍵つきのアドレスに送ると動く。`?wait=1` で結果を返す)、作業フォルダへのファイルの追加 | AIに頼む、判断する、ニュースを取る、知識ベース検索、ウェブページを読む、ウェブに送る、ファイルを読む・書く(上書き/追記)、文書を作る(Word・Excel・PowerPoint、上書き/追記対応)、コマンドを実行、Pythonを実行、行ごとにAI処理(`for_each`)、通知する(スマホ・PC)、条件に合わなければ止める(文字・正規表現・数値比較 `gt`/`lt`/`gte`/`lte`・JSONキー確認)、文章を組み立てる、待つ |

- 「朝のニュース要約」「追加ファイルの自動要約・記録」「知識ベース参照レポート」のテンプレートからすぐに作り始められます。

- 前の手順の結果は `{{prev}}`・`{{step2}}`、きっかけの内容は `{{trigger}}`(JSON なら `{{trigger.項目}}`)、今日の日付は `{{date}}`・`{{weekday}}` で差し込めます。判断の確率は `{{step1.probability}}`。
- 「AIで作る」に「毎朝8時に〜してスマホに通知」のように書くと、きっかけと手順の下書きを作ります(下書きは止めた状態で作るので、確かめてから有効にします)。
- ファイル・文書・コマンド・ウェブの手順は、エージェントと同じ道具を通して動くので、作業フォルダの外には届かず、書き換えの前にはバックアップが残ります。設定で許可していない種類の手順は、理由を記録して止まります。
- 自動化は確認なしで動くため、作る・変えるのは PC の画面からだけです。スマホからは、動かす・止める・実行の記録(手順ごとの結果)を見ることができます。

### プロジェクトを作る・フォルダの中を編集する(Codex や Claude Code のように)

- エージェントで「〜アプリを作って」と頼むと、**計画 → ファイルを1つずつ書く → 構文とテストで確かめる → 直す** の手順でプロジェクトを作ります([project.py](src/celestial/project.py))。小さいAIは1回の応答で多くのファイルを書き分けられないので、ファイルごとに、計画とそれまでのファイルを見せて書かせます。テストが落ちたら、テストを仕様として本体を直させ、同じ食い違いが残ればテストのほうを計画に合わせます。書く前に、計画をまとめて1回だけ許可を求めます。
- 実際に「数当てゲームの CLI アプリをテストつきで作って」で試し、12.7 秒で4ファイルを作り、テストに合格し、遊べることを確かめました(qwen2.5-coder:7b)。
- エージェントが変えたファイルは、Claude Code のようにファイルごとの増減(+12 −3)と差分で表示します(PC・スマホ)。
- エージェントが作業するフォルダは、会話ごとに PC の好きなフォルダを選べます(PC の画面の「フォルダ」。最近使ったフォルダから選び直せます)。Windows やプログラムの置き場は、権限が「すべて許可」のときだけ選べます。

### 判断(Jev のような System 1)

文章を作らずに、決まった選択肢(省略時は はい/いいえ)から1つを、確率つきで選びます([decide.py](src/celestial/decide.py))。AIに選択肢の記号を1語だけ答えさせ、その1語目の確率の分布(Ollama の top_logprobs)から選択肢ごとの確率を出すので、0.05〜0.2秒で済みます。

- 使える場所: 画面の「判断」、自動化の「判断する」手順(判断で分けて、後の手順に確率を渡す)、`POST /api/decide`(スマホや外のアプリから)、「覚えますか」の見分け。
- **較正**: AIの確率は自信過剰になりがちです(gemma3:4b は誤答でも 99.99% と言う)。正解の分かっている判断(文章の意味を読み取る30問と、担当の振り分け55問)をAIごとに解かせ、温度を学んで直します(温度スケーリング)。判断には、意味の判断で最も正確だったAIを使います。
- 計測の例(2026年11月):

| AI | 意味の判断(30問) | 担当の振り分け(55問) | 較正誤差(較正前→後) |
| --- | --- | --- | --- |
| gemma3:4b | 27問(90%) | 33問(60%) | 0.112 → 0.047 |
| qwen2.5:1.5b | 22問(73%) | 50問(91%) | — |

  判断の得意不得意は課題の種類で変わり、大きいAIが良いとは限りませんでした。振り分けだけで選ぶと、「本人の話か」の判断を半分しか当てられないAIが選ばれたため、意味の判断で選ぶようにしています。

### AIエージェント

「エージェント」をオンにすると、AIが道具を使いながら自分で段取りを組み、目標まで進めます。

| 種類 | 道具 | 使える条件 |
| --- | --- | --- |
| 基本 | 計算(正確な四則演算・関数)、専門のAIへの依頼 | いつでも |
| ファイル | 一覧(`list_files` / `tree`)・名前で探す(`find_files`)・読む(`read_file`: Office/PDF 含む)・中身を検索(`search_files`)・CSV/TSV/JSON配列を SQL で集計(`csv_query`)・SQLite 検索(`sqlite_query`)・Git 状態参照(`git_info`) | 作業フォルダを設定したとき |
| ファイルの変更 | 書く・部分を書き換える・追記・フォルダ作成・移動・コピー・削除・元に戻す・正規表現で一括置換(`regex_replace`)・zip/tar.gz の圧縮・展開・一覧(`archive`) | 「ファイルの変更を許可」 |
| Office 文書・グラフ | Word・Excel・PowerPoint のファイルを作る(Word・PowerPoint は `append` 追記にも対応)。Word・PowerPoint・PDF は読み取り対応、Excel は CSV や SQL として参照可。CSV・表・JSON から SVG / 対話的 HTML の棒・折れ線・円グラフを作成(`make_chart`) | 「ファイルの変更を許可」 |
| 実行 | Python の実行(`run_python` / `run_file`)・コマンドの実行(`run_command`)・常駐プログラム管理(`start_process` / `process_output` / `stop_process`)・ローカル URL 確認(`check_url`) | 「コマンドと Python の実行を許可」 |
| PC 操作 | アプリやファイルを開く・文字入力・キー操作・クリック・スクロール・ウィンドウの切り替えと終了・画面を見る・クリップボード・音量・再生の操作・PC の状態・実行中のプログラム | 「PC の操作を許可」 |
| ネット | Wikipedia で調べる(`wikipedia`)・最新ニュース(`news`)・ウェブページを読む(`fetch_url`)・HTTP API 通信(`http_request`) | 「ネットの利用を許可」 |
| 知識ベース・記憶 | 知識ベース検索(`kb_search`)・資料/メモ/URL の登録(`kb_add`)・利用者メモの保存/一覧/削除(`save_memory`) | いつでも |

#### 権限のモード

画面の「モデルと設定 → エージェント」で選びます(スマホからは変えられません)。

| モード | 動き方 |
| --- | --- |
| 読み取りのみ | ファイルを読む・探すだけ。変更やコマンドの実行はしません |
| 確認しながら | ファイルの変更・コマンドの実行・PC の操作の前に、毎回内容を見せて許可を求めます |
| 編集は自動 | 作業フォルダの中のファイルの作成・編集は自動。コマンドの実行と PC の操作の前に確認します |
| すべて自動 | 作業フォルダの中の編集もコマンドも自動。取り返しのつかないコマンドは止め、作業フォルダの外の変更・ネットからの取り込み・公開などの前だけ確認します |
| すべて許可 | すべてのコマンド・編集・PC の操作・ネットを、確認なしで許可します。作業フォルダの外も含め、PC のどこでも扱えます |

#### 小さいAIでも最後までやり遂げるための工夫

実際にエージェントに作業させ、失敗の原因を1つずつ調べて直しました([agent.py](src/celestial/agent.py)・[tools.py](src/celestial/tools.py))。

- **計画と1手ずつの実行**: 目標を1〜6の手順に分けて画面に出し、1手ごとに「考え・手順の番号・道具・引数」を JSON で出させます(形は文法で強制)。長いファイルは、書く役のAIに中身だけを書かせ、構文の誤りがあれば1回だけ書き直させます。
- **失敗は失敗として扱う**: プログラムの終了コードが 0 以外なら「失敗」として直させます。書いたスクリプトは run_file で、そのスクリプトのフォルダで動かします。
- **サーバーやウィンドウのアプリは自動で裏で起動**: 小さいAIはサーバーを普通の実行で動かしがちで、そのままだと時間切れまで待って失敗します。サーバーやウィンドウのアプリを動かすコマンド・ファイルは、終わるのを待たずに裏で起動し、受け付けを始めたポートを実際に開いてみた結果(`HTTP 200: hello` など)を返します。1回答えただけで終わるような作りは「動き続けるはずのものが終わった」として直させます。
- **時間切れで止まらない**: 時間切れのときは、シェルの先で動くプログラムごと止めます(サーバーが出力をつかんだまま残り、いつまでも戻らない、を防ぐ)。
- **Windows のコマンドの癖を直す**: Unix の書き方のまま来たコマンドを、cmd で動く形に直します。`git commit -m 'Initial commit'`(cmd では一重引用符が効かず、必ず失敗していた)、`mkdir -p a/b`(`-p` という名前のフォルダができていた)、`a; b`、`echo 'x' > f` など。直せないもの(`ls` や `cat` が無い PC)には、Windows での言い換えと、使うべき道具を添えます。
- **まとめて移動・コピー**: `photos/*2023*` のようなパターンや、`photos/a.jpg photos/b.jpg` のように並べた名前で、合うファイルをまとめてフォルダへ移せます(並べた名前を1つのファイル名として探し、「ファイルがありません」になっていました)。
- **行き詰まりの打ち切り**: 同じ呼び出しで同じ結果が3回続く、または4回続けて失敗したら止め、作業の記録だけを材料に普通の文章で報告します。
- **終わった作業を繰り返さない**: 何も変えないまま、成功したのと同じ呼び出しをもう一度しようとしたら、動かさずに「もう終わっている」と返します(小さいAIは、終わったあとも確かめ直しやコミットのやり直しを続けがちで、それが「行き詰まり」と判定されて失敗の報告になっていました)。続くときは、その時点で報告して終えます(失敗の注意は付けません)。同じ画面撮影や同じ URL の確認のように、様子を見るだけの同じ呼び出しを続けて3回以上しようとしたときも、新しいことは分からないので先へ進ませます。git の「コミットするものがない」も、すでにコミット済みとして扱います。
- **ポートの取り合い**: 作ったサーバーが待ち受けるポート(`port=8080` など)を、ほかのプログラムがもう使っていたら、起動しません(Windows では同じポートで2つが待ち受けられてしまい、そのプログラムへの接続を横取りすることがあるためです)。そのプログラム(PID と名前)を伝え、そのプログラムは止めさせません。ユーザーが番号を指定していなければ、空いている番号(調べて示します)に変えて起動し直させ、指定していた番号なら、変えずにユーザーに伝えさせます。Flask が「アクセス許可で禁じられた方法でソケットにアクセスしようとしました。」(WSAEACCES。日本語の Windows では番号なしでこの文だけが出ます)で終わったときも、ポートの取り合いとして扱います。Flask では、ユーザーが番号を言わなければ 5000 を使うよう伝えます。qwen2.5-coder:7b が、頼まれていないのに、この PC のほかのサーバーが使っている 8080 を選んだことがあったためです(以前の注意は「そのプログラムを止めてから起動して」と、止めるコマンドまで渡していました)。
- **Excel の表を確かめられる**: 作ったときと読んだときに、合計などの数式の結果を添えて表を見せます(`=SUM(B1:B3) → 383`)。見出しを付けない表や、文字の列を足す式(`=SUM(A2:A4)`。小さいAIが書きがち)は、作るときに数の列とデータの行に直します。
- **計画のずれを防ぐ**: 計画の例を写して、頼まれていないフォルダ(`todo-app` や `hello` など)を作ってしまうことがあったので、例はフォルダを使わない別の依頼(`greet.py` を作って動かす)にし、「名前は自分の依頼のものを使う」と明示しています。置き場所は、ファイル1つなら作業フォルダそのもの、ファイルがいくつもある新しいアプリなら中身の分かる名前のフォルダ1つ(`weather-signage` など)、ユーザーがフォルダ名を言ったらその名前のままです。計画にコードの1行が混ざったら取り除きます。
- **やったことの照合**: AIが「やりました」と答えても、実行記録に成功した操作がなければ、回答の先頭に訂正が付きます。
- **キーのいらない公開 API を知っている**: 天気(Open-Meteo)・大気の質・祝日・為替・地震について、登録なしで使える API の使い方(URL と、返ってくるデータの形)を、関係する依頼のときだけAIに渡します([knowhow.py](src/celestial/knowhow.py))。以前は「天気には API キーが要る」と思い込み、キーを取りに行こうとして止まっていました。サイネージやダッシュボードのような表示画面では、時計は JavaScript で毎秒、データは10分ごとに、ページを読み込み直さずに更新するよう伝えます。画面とサーバーの受け渡しの形(`/api/weather` が返す JSON の項目名)も決めて、両方を書くAIに同じく伝えます。書く役のAIには、画面を書くときはそれを返すサーバーのコードを、サーバーを書くときは画面を見せます(以前は、画面が存在しない項目名を読み、天気が undefined と表示されていました)。
- **続きの依頼で目的を忘れない**: 「続きから作成して」「作成して」のような発言では、会話の最初の依頼と前回の報告を目標に添えて計画します。調べものが要る依頼(「サイトで調べて、それを参考に作成して」)や続きの依頼を、新しいプロジェクトとして一から作り始めることもしません。作業が途中で止まった直後の短い発言(「openmeteo を使って」など)は、その作業への指示として会話の流れごと渡します。
- **作ったページを中まで確かめる**: エージェントがページを確かめるとき、そのページが読み込む JavaScript と、JavaScript が呼ぶ API(`fetch`)も同じサーバーで実際に開きます。無い URL(404)・サーバーのエラー・JSON に無い項目を読んでいるところが見つかれば、失敗として直させます(ページを開いただけでは、天気が undefined と出るような食い違いは分かりません)。
- **起動の遅いサーバーを待つ**: 起動したばかりのサーバーを確かめるときは、受け付け始めるまで最大 25 秒、ページの答えは 15 秒まで待ちます。起動の出力に別のポートが出たら、そちらを見ます。以前は起動の途中で「つながらない」と判定し、動いているのに「問題がある」と報告していました。Windows では、`0.0.0.0` で待ち受ける Flask が受け付けを始めるまでに 13 秒ほどかかることがあります(Python の `http.server` が起動のときに呼ぶ `socket.getfqdn("0.0.0.0")` が、この PC では 12 秒かかっていました。`127.0.0.1` ならすぐです)。
- **ページを書いたのに / が無ければ失敗にする**: サーバーは動いていて、templates/index.html などのページのファイルもあるのに、`/` を開くと 404 のときは、そのファイルを返す `/` の作り方を添えて直させます(小さいAIは API だけ作って `/` を忘れがちでした)。
- **直したサーバーは起動し直す**: 同じプログラムをもう一度動かしたとき、またはこれから使うポートでこの依頼のプログラムが待ち受けていたときは、古いほうを止めてから起動します(「前に起動していた app を止めて、起動し直しました」と伝えます)。以前は古いほうを残したまま2つ目・3つ目を起動していました。Windows では同じポートで複数が待ち受けられてしまうため、古いほうが答え続け、直した結果が見えないまま同じ直しを繰り返していました。この依頼の外で起動したもの(残すと言われたサーバーなど)には触りません。
- **サーバーの中のエラーは失敗として直させる**: 動いてはいても、ページを開くと HTTP 500 になるなら失敗として扱い、エラーの文(Flask のエラーのページの題名)と、サーバーが出した Traceback の最後を添えて返します(長いエラーのページの HTML は見せません)。テンプレートが、サーバーから渡されていない名前を使っているとき(`'now' is undefined`)は、`render_template` で渡すか、時計は JavaScript で出すよう伝えます。以前は 500 でも「成功」として扱い、テンプレートだけを書き換え続けていました。
- **エラーの文だけのページも失敗にする**: HTTP 200 でも、ページの代わりに短いエラーの文だけが返ってくるとき(Flask で `except Exception: return 'Error fetching weather data'` のように、例外を受けて文だけを返す作り)は、失敗として扱い、サーバーの出力(except が出した本当の原因)を添えて直させます。テンプレートから作ったページの一部が「取得できませんでした」なのは、外の API が止まっているときの正しい作りなので、失敗にしません。JSON の答えも見ません。gemma3:4b が、テンプレートの読み込みに失敗して「Error fetching weather data」とだけ返すページを作り、「正常に表示されました」と報告していたためです。
- **render_template に templates/ を付けた誤りを、書いた時点で知らせる**: `render_template('templates/index.html')` は templates フォルダの中の templates/index.html を探すので、ページを開くと TemplateNotFound になります。書いた直後に、そのまま edit_file に使える直し方(`'templates/index.html'` → `'index.html'`。名前を変数に入れてから渡す書き方も)を添えて知らせます。`template_folder` を変えているときや、本当にその場所にファイルがあるときは知らせません。
- **何も変えない編集を「編集しました」にしない**: old と new が同じ編集は、何も変わらないと返します(小さいAIが、直したつもりで同じ文字列を渡すことがありました)。
- **開いたページも中身を確かめる**: この PC の中のページ(`http://localhost:番号/`)を open でブラウザに開いたときも、同時にそのページを取得し、HTTP の番号・エラー・ページとサーバーの食い違いを添えます(500 などなら失敗)。小さいAIは、作ったページを「ブラウザで開いて画面撮影」で確かめようとし、画面撮影に別のウィンドウしか写っていなくても「表示されました」と報告していました。この依頼で起動したサーバー(依頼が終わると止めます)のページは、ブラウザーでは開かずに中身だけを確かめます(開いたタブは、サーバーが止まったあとも残り、動かないページのまま要求を出し続けるためです)。
- **報告の前に、動いているサーバーを開く**: 「完了しました」と報告する前に、この依頼で起動して動いているサーバーのページを実際に開き、ページが読み込む JavaScript と呼ぶ API まで確かめます。HTTP 500 などのエラー、エラーの文だけのページ、ページが呼ぶ API の 404 なら、報告させずにエラーの文を渡して1回直させます。作ったサーバーを最後に直したあと一度も動かしていなければ、Celestial が自分で起動して確かめます(小さいAIは、直したあと動かさずに「完成しました」と報告しがちでした)。直らないまま報告したときは、回答の先頭に「報告の時点で、起動したサーバーのページを開くとエラーでした」と付けます(AIの言い分より、開いた結果を正とします)。受け付けていない・HTTP でない・404 は、作りによっては正しいので挙げません。繰り返しや打ち切りで終わったときも同じように確かめ、その結果を「今の状態」として報告を書くAIに渡します(途中の失敗に引っ張られて、動いているのに「まだできていません」と書いていたためです)。
- **表示画面で決まって足りないものを確かめる**: サイネージ・ダッシュボード・時計を作る依頼では、報告の前にファイルの中身を見て、時計が動くか(JavaScript で毎秒表示し直しているか)と、天気が番号(weather_code)のまま出ていないかを確かめ、足りなければ続けさせます(qwen2.5-coder:7b は、開いたときの時刻のまま止まった時計や、「天気: 3」と出る画面を作って報告していました)。
- **直すたびの起動し直しを「繰り返し」に数えない**: 直すたびにサーバーを止めて起動し直すのは正しい手順なので、そのあいだにコードを動かし直していれば、同じ「止めました」が続いても打ち切りません。
- **def の行だけを old にした編集を、関数の単位で行う**: 小さいAIは関数を def の行で指し、そのまま置き換えると壊れる編集をしがちです(qwen2.5-coder:7b で実際にありました)。足す関数を `@app.route` のすぐ下に入れると、足した関数がページになってしまう、別の関数で def の行を置き換えると、元の関数の中身が新しい関数の return のあとに残る、などです。足すつもりの関数はデコレーターより上に足し、元の関数は残します。中身まで書き直した関数を渡したときは、元の関数を丸ごと置き換えます(どちらにしたかを返します)。名前を変えるだけ、中身の頭に行を足すだけの編集は、今までどおりそのまま置き換えます。
- **同じ名前の関数を重ねない**: もうある関数と同じ名前の関数を足す編集は保存せず、今ある場所を返します。Flask で `@app.route` を付けた関数の名前が重なっていると、起動したときに `AssertionError: View function mapping is overwriting an existing endpoint function` で止まるので、書いた時点で知らせ、同じ写しなら、後ろの写しを消す edit_file の引数を添えます。起動してすぐこのエラーで止まったときも、「同じ名前の関数が2つある」と直し方を伝えます(以前は「動き続ける作りに直して」とだけ伝えていたため、AIはポートの名前を変える編集を繰り返していました)。
- **作る前に使っている名前を、書いた時点で知らせる**: Python はファイルの上から順に動くので、`@app.route` の関数を `app = Flask(__name__)` より上に置くと、動かしたときに NameError で止まります(名前はファイルのどこかで作られているので、定義していない名前の確かめでは見つかりません)。書いた直後に知らせ、`app = Flask(__name__)` を上に移す edit_file の引数を2つ(上に足す・下の行を消す)添えます。`app = Flask(__name__)` が2回あるときも知らせます(2回目で app が作り直され、それより前に付けたページが消えて 404 になります)。qwen2.5-coder:7b が、/api/time を import のすぐ下に足して止まり、直そうとして上にもう1行 `app = Flask(__name__)` を足したため、/api/time が 404 のままでした。関数の中身・lambda・`if __name__ == '__main__':` の中で使うのは、あとで動くので知らせません。
- **起動した時点で、ページが呼ぶ API まで開く**: サーバーを起動したときの確かめでも、check_url と同じく、ページが読み込む JavaScript と呼ぶ API を開き、無い URL(404)などがあれば失敗として返します(以前は / を開くだけだったので、ページが毎秒呼ぶ /api/time が無くても「成功」でした)。
- **「完了しました」と言いながら作業を続けない**: 確かめ終えたあと(最後にコードを変えたあとに、動かすか開くかして成功した)で、考えが2手続けて「完了しました」なのに道具を使おうとしたら、その手は行わず、報告の前の確かめをします。足りないものがあれば続けさせ、なければそこで終えます(失敗ではないので注意は付けません)。qwen2.5-coder:7b が、動くサイネージを確かめたあと「作成と実行が完了しました」と書きながら、ファイルを別のフォルダへ動かして壊し、直そうとして手数の上限まで続けたためです。「正しく表示されていることを確認しました」のように、動くのを確かめたと言う考えも同じに扱います。
- **old が何か所もあるときは、場所を見せる**: 「3 か所にあります」だけでなく、行の番号と、それぞれの場所を1か所に決める old の例(上の行を足したもの)を返します。同じ名前の関数が重なっているなら、それも添えます。
- **datetime の使い方の誤りを、書いた時点で知らせる**: `from datetime import datetime` のあとに `datetime.datetime.now()`、`import datetime` のあとに `datetime.now()` と書くと、動かしたときに AttributeError で止まります。書いた直後に、そのまま使える直し方を添えて知らせます(両方の import があるときは、どちらも正しいので知らせません)。
- **同じ追加を重ねない**: すでに入っている行を、同じ場所にもう一度足す編集は保存しません(直らないと、同じ追加を3回繰り返し、同じ行が3つ重なっていました)。
- **外のサービスが答えないだけなら、コードの誤りにしない**: 天気の API などが時間内に答えず、サーバーのコードが例外を受けてエラーの JSON(`{"error": "... timed out"}`)を返しているなら、作りは正しいので直させません(そのあいだ、画面はその部分に「取得できませんでした」と出すよう伝えます)。Open-Meteo は、この PC からときどき長くつながらなくなり、そのたびに小さいAIが正しいコードを書き換えていました。つなぎ先の名前の誤りのように、待ち切れないのではなく見つからないエラーは、今までどおり誤りとして直させます。
- **ポートを先に使っているプログラムがあれば失敗にする**: サーバーを起動する前から、この依頼の外のプログラムが同じポートで待ち受けていたら、そのプログラム(PID と止め方)を添えて失敗として返します。Windows では、両方が同じポートで待ち受けられてしまい、確かめても古いほうが答えることがあるためです(専有されたポートへの接続が「使用中」ではなく `WinError 10013` になる場合も、取り合いとして扱います)。
- **答えが返らないページを「つながらない」と言わない**: サーバーにはつながったのに答えが返らないとき(ページを開くたびに外部の API を timeout なしで待っている、など)は、「つながりましたが、答えが返りませんでした」と、よくある原因(外部の API には timeout=5 を付け、失敗しても「取得できませんでした」と表示してページは返す)を、サーバーの出力と一緒に返します。以前は「接続できませんでした」と返していたため、天気の API が一時的に不調だったとき、AIはポートの番号や host の設定を直し続けていました。ページの答えは 15 秒まで待ちます。
- **出力に色の制御文字を混ぜない**: Python 3.13 以降は、`FORCE_COLOR` があるだけで(値が 0 でも)エラー表示に色を付けるため、`NO_COLOR` と `PYTHON_COLORS=0` も渡し、それでも残る制御文字は取り除きます(AIが読む出力に `\x1b[35m` のような文字が大量に混ざっていました)。
- **ワーカーにできないことは頼まない**: ワーカーのAIには、作業フォルダもプログラムの出力もネットも見えません。API キーの取得や、中身を渡さずに「weather.py の出力を解析して」と頼もうとしたら、理由と代わりの方法を返して止めます(以前は、同じ無理な依頼を繰り返して打ち切られていました)。
- **やり残しを確かめてから報告する**: 何かを作る依頼では、報告する前に1回だけ、依頼と、書いたファイルの今の中身(最後に書いた5つまで)を見比べさせ、頼まれたのにまだ無いもの(湿度を出すよう頼まれたのに、画面に湿度が無い、など)を最大4つ挙げさせます。見つかれば報告せずに作業を続けます(画面には「やり残しを見つけたので続けます: …」と出ます)。材料は作業の記録の言い分ではなく、ファイルの実物です。小さいAIは、一部だけ作って「完成しました」と報告しがちでした。
- **書いたコードの誤りをすぐ知らせる**: Python のファイルを書いた・直した直後に、構文の誤りと、定義も import もしていない名前を機械的に探し、その行と一緒に返します。エージェントはこれを失敗として扱い、動かす前に直させます(ただし保存はできているので、続けての失敗の数には入れません)([codecheck.py](src/celestial/codecheck.py))。gemma3:4b が `@app.route` を使いながら `app = Flask(__name__)` を書き忘れ、サーバーが起動直後に落ちていたためです(構文は正しいので、構文の確かめでは見つかりません)。どこかで一度でも作られている名前は知らせない、`*` の import や `globals()` があれば何も言わない、という害の少ない側に倒した確かめです(Python の標準ライブラリ 558 ファイルで試し、知らせたのは、わざと NameError を起こす1か所だけでした)。直し方が決まっている誤り(`datetime`・`os`・`requests` などの import 漏れ、Flask の `render_template` などの import 漏れ、`app = Flask(__name__)` の書き忘れ)には、そのまま edit_file に使える引数(`{"path": "web/app.py", "old": "import os", "new": "import os\n\napp = Flask(__name__)"}` など)を添えます。小さいAIは説明だけでは直せず、ファイルに無い行を old にした同じ編集を4回繰り返していました。同じ失敗を繰り返したときは、そのファイルの今の誤りと直し方をもう一度見せます。
- **構文を壊す編集は保存しない**: 構文の正しかった Python のファイルを、edit_file や append_file で壊す変更(関数の途中にプログラム全体を貼り付ける、など。実際にありました)は保存せず、壊れる行に印を付けたまわりの行を返します。new の字下げがずれているだけなら(小さな編集で、import や def を関数の中へ入れることにならないとき)、置き換える場所の字下げに合わせて保存します。
- **少しずれた old でも、場所が1か所に決まれば直す**: 小さいAIは、字下げを落とした行や、自分が直す前の形のままの行を old に渡し、「見つからない」を繰り返しがちでした。行ごとの空白を除けば一致する場所が1つだけのとき、または old が1行で、とても近い行(85% 以上で、2番目とは差がある)が1つだけあり、その違いが語の足し引き(と引用符の違い)だけのときは、その行を置き換え、どの行を置き換えたかを返します(Aider と同じ考え方です)。`'other.html'` と `'error.html'` のように別の語が違うときは、別の行かもしれないので置き換えません。それ以外は、似ている行と、行の足し方(足したい場所のすぐ前の行を old にする)を返します。
- **確かめ終えたサーバーを止めない**: 動いているサーバーは止めずに終えるよう伝えます(依頼が終わると Celestial が止めます)。最後に変えたあとで確かめて動いたサーバーを、頼まれていないのに止めようとしたら、その手は行わず、報告の前の確かめをして終えます。stop_process で止めたものは「止めました(止めたので、終了コードは誤りではありません)」と出し、止めたサーバーのポートを開こうとしたときは「止めたので、今は動いていません」と返します。qwen2.5-coder:7b が、動くサイネージを確かめたあと後片付けのつもりでサーバーを止め、開き直して「接続できません」になり、起動し直しては止める、を打ち切りまで繰り返したためです。
- **1つのファイルを書く手順はまとめる**: 計画で同じファイルの中身をいくつもの手順に分けたら(「app.py を作る」「app.py に天気の関数を作る」「app.py にルートを作る」)、1つの手順にまとめます。小さいAIは、1手で書き終えたファイルを手順ごとに作り直し、ページとかみ合っていた中身を壊していました。
- **同じ関数の写しを足さない・済んだ変更は済んだと言う**: edit_file の new に、ファイルにもうある関数と中身まで同じ写しがあれば、それを除いて残りだけを反映します(小さいAIは、前の編集の new を使い回して、もうある関数をまた足そうとしがちでした)。old が見つからなくても、new がもうファイルにあるなら「この変更は、もう済んでいます」と返し、Python のファイルなら、old が指していた関数の今の全体を見せます。同じ失敗した編集を繰り返したときも、その関数の今の全体を見せます。
- **行き詰まったら、一度だけ本当の状態を見せる**: 同じ種類の失敗が続いて打ち切る前に1回だけ、作ったサーバーを Celestial が起動してページを開き、今のエラー(または、もう動いていること)を見せて続けさせます。動かした結果は、何を直せばよいかをはっきり示すからです。
- **ページが確かめているだけの項目は、食い違いにしない**: ページの JavaScript が `if (data.error)` のように、あるかどうかを確かめているだけの項目と、error・message・status のようにエラーのときだけ返す項目は、API の答えに無くても食い違いにしません。以前は、天気が取れているのに「error が無い」として直させていました。
- **よそからの要求を見分ける**: サーバーの出力のアクセスログは、同じ要求を1行にまとめ(「同じ要求がほかに N 回」)、Celestial もページも開いていない URL への要求には、よそ(開いたままのブラウザーのタブなど)から来たものだと添えます。開いたままのタブが、前に作った別のページの /api/time を毎秒呼んでいて、AIがその 404 を直そうとしていたためです。
- **頼まれていないのに、作ったファイルをアプリで開かない**: この依頼で作った・変えたファイルを、開くよう頼まれていないのに open しようとしたら、アプリでは開かずに中身を見せます(確かめのつもりで、利用者の画面に Excel が開くところでした)。作業フォルダの中のファイルは、作業フォルダから開きます(以前は Celestial を動かしているフォルダから探して「見つかりません」を繰り返していました)。check_url に `file:///...` を渡したときも、作業フォルダの中のファイルなら中身を読んで返します。Word・Excel・PowerPoint を作った結果には、中身はこのとおりで出来上がっていると添えます。qwen2.5-coder:7b が、作った Excel を open と file:// の確かめで何度も開き直していたためで、計測の Excel の課題は 46.3 秒から 5.2 秒になりました。
- **やり残しは、依頼にあるものだけ**: 報告の前のやり残しの確かめで挙がったものは、依頼の文に出てくるものだけを残します(頼まれていない「風速」を足させていました)。天気・気温・湿度・時刻・日付は、ページの HTML と JavaScript がもう出していれば挙げません(もう表示している温湿度を「無い」と挙げていました)。
- **ファイルを名前でも探す**: search_files は、中身だけでなくファイルの名前も探します(`IMG_2023_*` のようなパターンも使えます)。中身が空の写真を名前で探して「見つかりませんでした」になっていました。
- **文字列を切った改行を戻す**: Python のファイルを書く・直すとき、`print('Starting...\n')` の `\n` が JSON の中で本当の改行になって文字列が閉じていなければ、`\n` の2文字に戻して保存します(戻して構文が通るときだけ)。小さいAIには JSON の中で `\\n` と書き分けるのが難しく、同じ誤りを直せずに打ち切られていました。
- **読まずに書き直させない**: 前からあるファイルを、この依頼で読まないまま write_file や write_code で丸ごと書き直そうとしたら止め、読んでから、直す所だけを edit_file で直させます(Claude Code と同じ決まりです)。gemma3:4b が、calc.py も、それを使う test_calc.py も読まずに calc.py を書き直し、テストが使う mul を消していました。今の中身とまったく同じ中身を書こうとしたときは「何も変わりません」と返し、`ImportError: cannot import name 'mul' from 'calc'` には、calc.py に mul が無いことと、ほかのファイルが使う名前は残すことを添えます。同じ書き直しを繰り返していても、最後の実行が失敗したままなら、「成功の繰り返し」ではなく行き詰まりとして注意を付けます(以前は「テストが通りました」と報告していました)。
- **報告を確かな中身にする**: 報告には、作ったもの・使い方(起動のコマンドと URL)と、記録や終わりの状態で分かるやり残しだけを書かせ、手順を1つずつ並べさせず、コードも貼らせません。報告の材料の記録では、続けて同じ確かめは1つにまとめます。書いたコードがキーの要らない API(Open-Meteo など)を使い、キーらしい名前をどこにも使っていないのに、報告が「API キーを設定していない」と書いたら、その文を除きます(天気を出せているサイネージで、「APIキーを設定していないため、天気情報が表示されません」と報告していました)。打ち切ったときの報告に貼られた、実際のファイルと違う長いコードも除きます。
- **計測と試しは、利用者の画面や設定に触れない**: エージェントの計測(`celestial bench --agent`)は、作業フォルダの中のファイルとコマンドだけを使う囲い(sandbox)で動かします。PC の操作・ネットの道具・作業フォルダの外には届きません。以前は、利用者の権限の設定のまま許可を自動で出して動かしていたため、ブラウザーにタブが開き、1回は利用者の画面を撮っていました(撮った画像は、この PC の中のAIが読んだだけで、外には出ていません)。
- **画面を撮るのは、画面やアプリの操作の依頼のときだけ**: 依頼に画面・ウィンドウ・クリック・入力などの言葉が無く、この依頼でまだ PC を操作していなければ、screenshot は撮らずに、作ったファイルは read_file で、作ったページは check_url で確かめるよう返します。
- **新しく作る表の合計を、上の数と合わせる**: make_excel で新しく作る表の「合計」「平均」の行の数が、上の数から計算した値と違えば、`=SUM(B2:B4)` のような数式にして、直したことを結果に添えます(gemma3:4b が、合計の行に違う数を書いていました)。前からある表を書き足すときは、元の数を変えません。
- **フォルダの中身も一緒に見せる**: list_files は、フォルダごとに中のファイルの件数と名前(6つまで)を添えます。ファイルを渡されたら「フォルダがありません」ではなく、そのファイルの大きさと、read_file で読めることを返します。move_file・copy_file にフォルダそのものを渡したら、中のファイルをまとめて移すパターン(`photos/*2023*`)の書き方と、中のファイルを返します。まだ無いフォルダへの写し(`photos/2023/`)はフォルダとして扱い、copy_file の結果には、元のファイルも残っていることを添えます(gemma3:4b が、写真を写しただけで「年ごとに分けました」と報告していました)。
- **小さいファイルで old が見つからなければ、全体を見せる**: 60 行・3000 文字までのファイルなら、今の全体をその場で見せ、old はそこから写させます(gemma3:4b が、読んだあとでも、ファイルに無い行を old にした編集を4回続けて打ち切られていました)。読まずに書き直させない決まりでは、依頼の前からあるファイルと、この依頼で動かしたプログラムが作った・変えたファイルとで、言い方を分けます。
- **標準ライブラリだけの Web サーバー**: Flask などを使わない Web サーバーの依頼には、`BaseHTTPRequestHandler` の `do_GET` で自分の文字を返す書き方を渡します。`SimpleHTTPRequestHandler` はフォルダの中のファイルを返すだけです(gemma3:4b が、hello をコンソールに print するだけのサーバーを書き、「hello と表示されます」と報告していました)。
- **「このフォルダ」は作業フォルダ**: 「このフォルダを git リポジトリにして」で、頼まれていない git_repo フォルダを作っていたので、決まりに書きました。計画で、同じ Word・Excel・PowerPoint のファイルを埋める手順が分かれていたら、1つにまとめます。
- **自動選択は、直近3回の計測を合わせて決める**: エージェントのAIの自動選択は、モデルごとに、最新の課題集での直近3回の計測を合わせた成功率で比べ、同じくらいなら速いほうを選びます。以前は最新の1回だけで決めていたため、gemma3:4b が 6/9・4/9 のあと、たまたま 9/9 で 0.2 秒速かった1回で、qwen2.5-coder:7b と入れ替わっていました。
- **Flask は、この PC で待ち受ける**: ほかの機器から見る依頼でなければ、`app.run(host='127.0.0.1', port=5000)` の書き方を渡します。この PC では `0.0.0.0` で待ち受けると、起動のたびに名前の問い合わせ(`socket.getfqdn`)で 12 秒ほど待ち、起動に 14.5 秒かかっていました(127.0.0.1 なら 0.8 秒)。スマホ・タブレット・LAN・Tailscale などから見る依頼のときだけ `0.0.0.0` にし、`http://<この PC のアドレス>:5000/` で開けることを添えます。
- **外のサービスが答えないときは、コードを直させない**: ページや API が何秒も待ってからエラーの JSON を返したら、1回だけ開き直します。2回とも同じなら、外のサービス(天気の API など)が答えていないと判断し、コードは直させずに、その部分は「取得できませんでした」と出すよう伝えます(同じ URL は2分のあいだ待ち直しません)。HTTP 200 でも中身が `{"error": ...}` の答えは、ページが読む項目の照らし合わせに使いません。Open-Meteo が答えなかった数分のあいだ、AIはエラーの答えを「食い違い」として直そうとし、答えに `'humidity': None` を足していました。
- **同じ確かめは、2回目から開かない**: 最後に変えたあとに check_url で確かめた URL をもう一度開こうとしたら、開かずに報告の前の確かめへ進みます(外のサービスが答えなかったときだけ、もう1回開けます)。
- **画面の JavaScript と CSS の手順は、HTML の手順にまとめる**: 計画に、ファイルの名前の無い「JavaScript で時計を動かす」のような手順があり、.js や .css のファイルを別に作らない計画なら、HTML を書く手順に合わせます。
- **ページの JavaScript の構文を確かめ、`\n` の誤りを直す**: ページ(HTML の `<script>` と .js)を保存するたびに、node で構文を確かめます。JSON の中で二重に書いたため、改行のつもりの `\n` の2文字が `<script>` に入り、ブラウザーでは動かない形がありました(確かめはすべて通っていました)。そのときは本当の改行に直して保存します。直せない誤りは、行と前後の行を添えて知らせます。
- **ページの JavaScript を、実際に動かして確かめる**: ページを開いたら(check_url など)、ページの JavaScript を node の上で動かします([pagerun.py](src/celestial/pagerun.py))。HTML から要素を作り、fetch には同じサーバーの実際の答えを返し、時計などのタイマーも数回呼びます。そのほかのブラウザーの機能は、何をしてもエラーにならない代わりのもので受けます(外のサイトは開きません)。止まるエラー(HTML に無い要素を探して null になる・head の中の script が要素より先に動く・名前の打ち間違い)と、画面に出る文字(天気が番号のまま・undefined・NaN)を見つけ、何が表示されたかも知らせます。開いただけの確かめと、ファイルの中身の確かめでは分からなかったためです。これまでの試しで作られたアプリ32個を動かして確かめると、正しく表示されるページを誤って咎めたものは1つも無く、成功と数えていた1回が、実は天気を「2」と表示していたことが分かりました(天気を文字にする関数のあとで、別の関数が番号で上書きしていました)。
- **行の一部を直す編集で、行の残りを消さない**: old が行の一部(`<div class="weather">{{ ... }}</div>` の `{{ ... }}`)で、そのままでは見つからず近い行を置き換えるときは、old に当たらない行の前と後ろを残します。以前は行の全体を new にしたため、`<div class="weather">` が消え、ページの JavaScript が止まっていました。置き換えても中身が変わらない編集は、ファイルを変えずに「もう済んでいます」と返します(時刻だけが変わり、下の「起動したあとで変えた」の確かめが毎回働いて、同じ編集と起動し直しを4回繰り返していました)。
- **起動したあとでコードを変えたサーバーでは、確かめにならない**: check_url で開いたサーバーが、起動したあとで変えた .py やテンプレートのまま動いていたら(debug や再読み込みで自分で読み直すものを除く)、失敗として起動し直させます。書き直す前のサーバーが答えて「成功」になり、報告の前に起動し直すと HTTP 500 でした。
- **テンプレートから Python の関数を呼んだとき**: `UndefinedError: 'weather_code_to_text' is undefined` のように、テンプレートが Python の関数を呼んでいるときは、`@app.template_global()` を付ける edit_file の引数か、Python で呼んで結果を渡す直し方を渡します(直し方が分からず、old と new が同じ編集を繰り返して打ち切られていました)。
- **天気の文字は、実際に表示する所で確かめる**: ページが番号(weather_code)を読んで自分で文字にしているなら、ページの中を確かめます。ページの JavaScript がサーバーから受け取った天気をそのまま書き込むなら、テンプレートの `{{ }}` の中の文字は数えません(開いたすぐあとに、JavaScript が番号で上書きするため)。晴れ・曇りの番号しか文字にしていない(雨・雪の日は「不明」)ときも戻します。
- **Python のファイルには Python だけを書かせる**: 書く役のAIの決まりに、ファイルの種類の言語だけで書くこと(.py は Python のコードだけで、Flask のページは templates/index.html)を足しました。.py に HTML のページを書いたら、それと分かる言い方で書き直させ、それでも HTML のままなら、エージェントに「edit_file では直らない。write_code で Python として書き直す」と伝えます。計画で画面の手順をまとめるときも、「同じファイルに」ではなく「この index.html の中に」と名前で書きます。「同じファイルに」が app.py の指示にも「HTMLとCSSを同じファイルに書きます」と移り、app.py に `<!DOCTYPE html>` から始まるページが書かれ、エージェントは CSS の行に注釈を足す編集を繰り返して打ち切られていました。
- **報告を整える**: 保存のときの自動の直し(改行・字下げ)は報告に書かせず、API の答えや、ファイルの大きさ・文字数も貼らせません。長いコードを除くときは、それを紹介する「以下の通りです:」の行も除きます(紹介の行と、除いた跡だけが残っていました)。

#### サイネージの依頼での試し

利用者の実際の依頼「pythonでflaskを使用し、天気情報や温湿度、時間などを表示する個人用のデジタルサイネージを作成して。」を、空のフォルダで qwen2.5-coder:7b に繰り返しやらせ、できたものを Celestial の外で起動し直して確かめました(ページが開くか、ページが読む項目名と API の答えが合うか、Open-Meteo の実際の天気と温湿度が出るか、時計が毎秒動くか、API キーの仮の値が入っていないか)。

安全のための決まり([tools.py](src/celestial/tools.py)):

- ファイルの道具は作業フォルダの外に届きません。書き換え・削除の前に必ずバックアップを取り、「元に戻す」で戻せます。
- 影響のある操作(ファイルの変更・実行・入力・クリック・アプリを開く など)の前に、内容を見せて許可を求めます。PC でもスマホでも許可できます。
- 文字入力やキー操作は、送り先のウィンドウを確かめてから行います。
- AIが「やりました」と答えても、実行記録に成功した操作がなければ、回答の先頭に訂正が付きます(小さなモデルは、やっていないことをやったと言うことがあるため)。
- ネットの道具は公開されているページだけを読み、家庭内の機器やこの PC 自身には触れません。

### 見る(画像・カメラの認識)

**PC**(画面の「見る」): PC のカメラ・PC の画面・画像ファイルを、PC の画像を扱えるAI(gemma3:4b など)が読み取ります([vision.py](src/celestial/vision.py))。

| モード | 内容 |
| --- | --- |
| 説明・文字を読む・物を数える・翻訳・表にする・問題を解く・コードを読む・質問 | 1枚の画像について。物を数えるは、物の名前と数を決まった形(JSON)で出させてから表示します |
| 周りの様子 | 目の不自由な人に向けて、前にあるもの・人・障害物を短く伝えます(読み上げと合わせて使えます) |
| 見張り | カメラの映像に動きがあったときだけAIに読ませ、何が起きたかを記録に並べます |

- 「ライブ」で、数秒おきに最新の映像を読み取ります。結果は読み上げ・コピー・「この画像で会話する」で会話に送れます。
- スマホのアプリからも `POST /api/vision` で使えます(PC の画面を読むのは、スマホからの PC 操作を許可しているときだけ)。

**スマホ**(アプリの「見る」): カメラの映像を、端末の中だけで認識します(Google ML Kit。映像を外へ送りません)。

| モード | 内容 |
| --- | --- |
| 文字 | 日本語と英数字の文字を読み取り、映像の上に枠で示します |
| 物と様子 | 写っている物の検出と、場面のラベル(犬・料理・空 など。日本語で表示) |
| QR・コード | QR コード・バーコードを読み、URL や Wi-Fi などの種類も示します |
| 顔 | 顔の位置と、笑顔・目の開き具合 |
| 翻訳 | 読み取った文字を、端末の中で日本語⇔英語に翻訳します(翻訳のモデルは初回だけ取り込み。Wi-Fi のときだけにもできます) |
| 質問 | 止めた1枚について質問します。端末内のAI(読み取った文字やラベルを渡して答えさせる)か、「PC で詳しく」で PC の画像AI に聞けます |

- 撮影・画像を選ぶで止めた1枚を読み取れます。読み取った文字は、そのまま会話に送れます。

### スマホアプリ

| 画面 | できること |
| --- | --- |
| 見る | カメラの映像を端末の中で認識(文字・物と様子・QR とバーコード・顔・翻訳・質問)。上の「見る」を参照 |
| 会話 | スマホの中のAIか PC のAIかを選んで質問。PC ではエージェントも使え、操作の許可もスマホからできる。音声入力(入力欄のマイク。できれば端末の中だけで文字にする)、音声会話(手を使わずに、聞く→答える→読み上げる→また聞く を繰り返す。「終わり」で止まる)、「覚えますか」の提案、エージェントが変えたファイルの差分、画像・文字のファイルの添付、ほかのアプリからの共有の受け取り、回答の読み上げ(記号やコードは読まず、表は1行ずつ区切って読む。読み上げ中はボタンが「止める」に変わる)と共有、出典の表示、回答を Word・Excel・PowerPoint で保存 |

| ファイル | PC の作業フォルダを見る・ダウンロード(途中から再開できる)・アップロード・フォルダ作成・削除(バックアップに移動) |
| 設定 | AIモデル(PC に入っているモデルをスマホに取り込み、スマホの中で動かす。速さの計測)、PC との接続、あなたに合わせる(AIへの指示・覚えていること)、PC への送信(文字・URL・クリップボード)、PC からの受信箱、見た目、通知、アプリの更新(PC に新しい版があれば、その場で受け取って入れ替える) |

- スマホの中のAIは llama.cpp で動き、通信なしで答えます。CPU の機能(dotprod / i8mm)に合わせて最適な版を自動で選びます。
- スマホの中のAIも、PC から同期した「AIへの指示」「覚えていること」と今日の日付を使います(PC につながっていないときは、前に受け取った内容)。「覚えて」などと短い日付の質問は、PC と同じ決まりでAIを使わずに答えます。

- PC で回答が終わったとき、スマホに通知できます。

## 精度と速さの工夫

```
依頼 → キャッシュ → 振り分け(学習済みルーター → 管理AI → キーワード)
     → 担当のAIが回答(実績で選ぶ)
         ├ 出だしを確かめる: 自信がない・言語を取り違えた → より正確なAIが答え直す
         └ 事実の短い質問で自信がない → Wikipedia で確かめて答え直す(ネット許可時)
     → [検証] → 記録・学習
複合的な依頼は 管理AIが分解 → ワーカー群が並列処理 → 統合
```

| 仕組み | 効果 | 実装 |
| --- | --- | --- |
| 回答キャッシュ | 同じ依頼は計算なしで即答。悪い評価で無効になる | [store.py](src/celestial/evolve/store.py) |
| 学習済みルーター | 管理AIの振り分けを覚え、自信があれば管理AIを呼ばない | [router.py](src/celestial/evolve/router.py) |
| 振り分けの安全策 | 「コード」「翻訳」「抽出」「要約」は、依頼にそれらしい手がかりがあるときだけ選ぶ(メールアドレスの抜き出しをコードの担当に回す、などの自信満々の誤りを防ぐ)。55問の振り分けは 50→53問が正しくなった | [workers.py](src/celestial/workers.py) |
| モデル選び | 担当ごとに「品質 − 所要時間」の実績が良いAIへ寄っていく(UCB)。精度の計測結果を事前の実績として混ぜる | [manager.py](src/celestial/manager.py) |
| 経験記憶 | 良い評価の回答を、似た依頼の手本として渡す。埋め込みモデルがあれば意味の近さで探す | [memory.py](src/celestial/evolve/memory.py) |
| 確からしさでの答え直し | 回答の出だし(40トークン)の確率から自信を測り、低ければ打ち切って、計測で最も正確なAIが答え直す。打ち切るまで画面には出さない。境目は計測の結果から学ぶ | [manager.py](src/celestial/manager.py) |
| 言語の取り違えの防止 | 日本語の依頼には日本語で答えるよう明示する。それでも中国語や英語で答えたら答え直す | [manager.py](src/celestial/manager.py) |
| 事実の裏付け | 事実の短い質問で自信がないときだけ Wikipedia を調べ、資料を見せて答え直す。検索で当たった本文の箇所を資料の先頭に置き、「長さ順の日本の川一覧」のような順位の一覧には「1位は信濃川」と書き添える(名前の並びだけでは小さいAIが読み取れないため)。出典を表示する | [ground.py](src/celestial/ground.py) |
| 日付の計算 | 日付が関わる依頼にだけ今日の日時を渡し、日数・曜日はプログラムで計算した値を渡す。「大晦日まであと何日?」は 0/2 問から正解に、短い日付の質問は計算でそのまま答える | [manager.py](src/celestial/manager.py) |
| 繰り返しの打ち切り | 小さいAIが同じ文を書き続け始めたら、その場で止めて1回分だけを残す(PC・スマホとも) | [base.py](src/celestial/backends/base.py) |
| 入れ替えを避ける | 読み込み済みのモデルを優先し、メモリからほかのモデルを追い出すような選び方は、はっきり正確なときだけにする | [manager.py](src/celestial/manager.py) |
| 公平な比較 | 課題集が変わったら、今の課題集で測った結果だけでモデルを比べる | [store.py](src/celestial/evolve/store.py) |
| 自作AI | 普段の利用と自習のデータで小さなモデルを学習し、得意な担当で使う | [train.py](src/celestial/train.py) |

### 確からしさでの答え直しについて

AIは各トークンを出すときの確率を返せます。出だしの平均の対数確率が低い回答は、誤答であることが多いと分かりました。

予備実験の結果(50問。回答の出だし40トークンの、対数確率の平均):

| | 正解の回答 | 誤答 |
| --- | --- | --- |
| qwen2.5:1.5b の平均 | -0.25 | -0.40 |

答え直す境目は、モデルを固定した精度の計測で記録した「問題ごとの確からしさと正誤」から、正解数が最も多く、その中で最も速くなる値を選びます(計測がまだなら -0.25)。計測するたびに学び直します。

小さいモデルは日本語の質問に中国語や英語で答えてしまうことがあります。日本語で答えるよう明示すると、12問中5問しか日本語でなかったのが12問とも日本語になり、正解も4問から8問に増えました。

## Word・Excel・PowerPoint・PDF・グラフ

追加のライブラリなしで、Office のファイルの中身(ZIP に入った XML)を直接読み書きし、PDF テキストの抽出と SVG / HTML グラフの生成も行います([office.py](src/celestial/office.py))。エージェントの道具と、回答の「保存」・会話全体の「Word書き出し」で使います。

| 種類 | 内容 |
| --- | --- |
| Word | 見出し・箇条書き(番号は段落ごとに 1 から)・表・コード・太字。新規作成に加え、既存 `.docx` への追記(`append_docx` / `mode="append"`)と読み取りに対応 |
| Excel | 1行目は見出し(固定・強調)。数・桁区切り(1,200)・パーセント・単位つきの数(1,200円、¥1,500、12件、▲300円)は数として入れ、単位は表示の形で見せるので、合計などの数式が正しく計算されます。複数のシートも作れます |
| PowerPoint | 見出しごとに1枚(表紙・箇条書き・表)。見出しのない回答は、内容を区切ってスライドにします。既存 `.pptx` へのスライド追記(`append_pptx` / `mode="append"`)と読み取りに対応 |
| PDF | 標準ライブラリだけで圧縮ストリーム(`FlateDecode`)・フォントの文字対応(`ToUnicode CMap`)・テキストブロックを解析して読み取り可能(`read_pdf_text` / 知識ベース / `read_file`) |
| グラフ | CSV・Markdown 表・JSON から棒グラフ(`bar`)・折れ線グラフ(`line`)・円グラフ(`pie`)を `.svg` または集計表つき対話的 `.html` として出力(`make_chart` / `render_chart`) |

Excel の数式の工夫:

- `=SUM(above)` と書くと、見出しの下からその行の上までの範囲になります(表の大きさを数えなくてよい)。
- 「合計」の行の SUM の範囲が短すぎる・自分の行まで含めて循環参照になる、といった小さいAIの誤りを直します。
- AI が数で書いた「合計」「平均」は、上の行の合計・平均と一致するときだけ数式に置き換えます(値は変えず、あとでデータを直しても合計が追従します)。合わないときはそのままにします。

AI は両端の `|` を省いた表(`月 | 売上` の次の行が `--- | ---`。GFM では正しい書き方)もよく書くので、PC の画面・スマホ・Office の書き出しのどれでも表として扱います。

作ったファイルは、Word・Excel・PowerPoint で開いて確かめています(Excel では数式の結果も計算させて確認)。

## 精度の計測

答えを機械的に採点できる課題集([bench_tasks.py](src/celestial/bench_tasks.py)、55問)を解かせ、正解率・振り分けの正しさ・平均の所要時間を記録します。

- 計測は会話の履歴にもキャッシュにも触れないので、学習状態を変えません。
- `--model` で全ワーカーを1つのモデルに固定でき、モデル同士や自作AIとの比較に使えます。固定した計測の問題ごとの結果は、答え直しの境目の学習に使われます。
- 自動でのモデル選びは、今の課題集で計測したモデルの中から行います。新しく入れたモデルは、「精度の計測」で測ると候補に入ります(`celestial bench --model 名前`)。
- コードの課題は、モデルが書いた Python コードをこの PC 上で実行して採点します。`--run-code`(画面では「コードの課題も採点する」)を付けたときだけ対象になります。
- 独自の課題集は `--tasks 課題.jsonl` で指定できます。

### 計測結果の例

組み込みの55問(計算と推論16・一般の知識22・翻訳5・抽出5・要約2・コード5)。2026年11月、GPU は RTX 5060(8GB)。

| 方式 | 正解 | 1問の平均 |
| --- | --- | --- |
| qwen2.5:1.5b だけ | 32 | 0.70秒 |
| gemma3:4b だけ | 48 | 1.41秒 |
| qwen2.5-coder:7b だけ | 46 | 2.06秒 |
| 自作AI(初期 0.5B)だけ | 21 | 0.52秒 |
| 自作AI(1.5B / LoRA+, q8_0, `celestial-v9`)だけ | 39 | 0.51秒 |
| 自作AI(3B / LoRA+・CPUオフロード, q4_k_m, `celestial-v11`)だけ | 46 | 0.55秒 |
| 自動(答え直し・入れ替えを避ける・振り分けの安全策) | 48 | 1.06秒 |
| 自動(Wikipedia での裏付け) | 50 | 1.25秒 |
| 自動(3B自作AI `celestial-v11` 等との分担・コード採点込み) | 50 | 2.09秒 |

- 3B 基礎モデル(`Qwen/Qwen2.5-3B-Instruct`)を LoRA+・KL 正則化・DPO・検算済み問題で学習した `celestial-v11` 単体で、初期 0.5B の **21/55 → 46/55 (84%)** まで向上し、平均応答も **0.55秒** に抑えています(抽出 5/5・要約 2/2・翻訳 5/5・推論 14/16・コード 4/5、振り分け 54/55)。
- `celestial-v11` を組み込んだ `自動` アンサンブルは **50/55 (91%)**(コード 5/5・抽出 5/5・翻訳 5/5・要約 2/2・推論 14/16・一般 19/22) を達成し、抽出・翻訳などを超高速(0.06〜0.55秒)な自作AIに任せつつ精度を両立しています。
- Wikipedia での裏付けは、「光の三原色」「世界一広い海洋」のような言い間違いを直しました。検索で答えの載った項目が見つからない問題(初代内閣総理大臣など)は直せません。
- 小さいモデルは回答にばらつきがあり、同じ設定でも数問ほど上下します。
- 繰り返しの打ち切りで、自作AIの平均は 4.21秒→0.52秒、qwen2.5:1.5b は 1.07秒→0.70秒 になりました。

## 自作AI

Celestial 自身が小さなモデルを学習し、配布モデルと同じ土俵で使い分けます。

```
自習(教師生成 + 検算済み問題 + Wikipedia Q&A + DPO比較) ─┐
普段の利用(悪い評価を除いた回答・修正前後の選好ペア)       ─┴→ 学習(LoRA+/KL/DPO) → 自作AI → 精度計測・自動分担
```

| 手順 | コマンド | 内容 |
| --- | --- | --- |
| 自習 | `celestial study --per-role 15` | 計測で最も正確なAIが担当ごとに練習問題を作って解く(非自己完結・計測類似は除外)。`--synthetic` で検算済みの推論・抽出・翻訳・要約問題、`--wiki` で Wikipedia 根拠の一般知識 Q&A、`--verify` で自動検算、`--contrastive` で DPO 比較ペア収集、`--focus-weak` で弱点補強、`--review` で既存データ見直しが可能 |
| 学習 | `celestial train` | プリセット(`0.5b`・`1.5b`・`1.5b-coder`・`3b`、または VRAM に応じた `auto`)に rsLoRA + LoRA+ で学習し、`celestial-v1`, `v2`… として保存。終了後に Ollama へ書き出し、精度を計測する |
| 自動進化 | `celestial evolve` | 診断 → `--review` 見直し → 重点自習・検算問題・Wikipedia Q&A → 学習 → Ollama 書き出し・計測を一括実行 |
| 利用 | (自動) | 自作AIは他のモデルと並んで候補になり、得意な担当(抽出・翻訳など)で高速に選ばれる。自信のない回答は、より正確なAIが答え直す |

学習には追加のライブラリが必要です(合計で数GB)。

```bash
uv pip install torch --index-url https://download.pytorch.org/whl/cu128
```

```bash
uv pip install transformers peft gguf
```

- 基礎モデルを凍結して `rsLoRA` + `LoRA+`(`--loraplus`)・`NEFTune`・長さ均等化損失で重みを更新し、基礎モデルを別メモリにコピーしない `KL正則化`(`--kl-beta`)と SFT 後の `DPO` 選好学習で記憶の忘却と誤答を防ぎます。
- 0.9B 以上のモデルでは勾配チェックポイントと 128 トークン分割出力層を自動で有効にし、`--offload` で最適化状態(AdamW)を CPU へ逃がすことで 8GB の GPU(RTX 5060 等)でも **3B モデル** を安定学習できます。
- 周回ごとに検証用データで確かめ、最も良かった時点の重みを採用します(DPO 後に検証損失が大きく悪化した場合はロールバック)。
- 学習後は LoRA を基礎モデルに合成して GGUF(`q8_0` / `q4_k_m` / `f16`)に変換し、Ollama に登録します([ollama_export.py](src/celestial/ollama_export.py))。スマホにも取り込めます。

| `celestial publish-app` | 作ったスマホのアプリ(APK)を、PC から配れる場所に置く(スマホのアプリの「更新する」で入れ替えられる) |
| `celestial models` | 利用可能なモデルと、管理AIに使われているモデル |
| `celestial study` / `celestial train` / `celestial evolve` | 自習(`--wiki`・`--synthetic`・`--verify`・`--contrastive`・`--focus-weak`・`--review`)で学習データを貯める / 自作AIを学習する(`--preset`・`--loraplus`・`--offload`・`--quantize`) / 自動進化を一括実行する |
| `celestial kb list\|add\|search\|rm` | ローカル知識ベース(RAG)へメモ・ファイル・フォルダ・URL を登録・検索・削除する |
| `celestial export data.jsonl` | 学習用のデータを書き出す |

## 設定

画面の「モデルと設定」で変えられます。ファイルで決めるときは [celestial.toml](celestial.toml) を使います(カレントディレクトリのもの。`CELESTIAL_CONFIG` で指定可)。画面で変えた設定はファイルより優先されます。

会話の題名を AI に付けさせたくないときは、celestial.toml の `[manager]` に `auto_title = false` を書きます。

## 安全とプライバシー

- 画面(PC の中)は 127.0.0.1 だけで待ち受け、他のサイトからの呼び出しは拒否します。プロキシを通った通信(X-Forwarded-For や Tailscale Funnel の印があるもの)も拒否するので、誤って Funnel などで公開しても鍵なしでは使えません。
- スマホからの接続は Tailscale のアドレスだけで受け付け、登録した端末の鍵(PC にはハッシュだけを保存)がなければ何もできません。
- 作業フォルダ・道具の許可・スマホからの接続と操作の許可は、PC の画面からしか変えられません。
- 「スマホからの PC 操作を許可」をオフにすると、画面の送信と遠隔操作を止められます。
- ネットを使うのは「ネットの利用を許可」をオンにしたときだけです(Wikipedia で調べる・指定されたページを読む・事実の裏付け・最新のニュース)。ニュースの検索に送るのは、依頼から読み取った話題の言葉(「AI」など)だけです。

## スマホアプリのビルド

[app/](app/) が Flutter のアプリ、[app/packages/celestial_llm/](app/packages/celestial_llm/) がスマホの中でAIを動かす部分(llama.cpp を同梱)です。

PC では [Celestial.cmd](Celestial.cmd) で開く画面(専用ウィンドウ)が基本です。同じ会話を Flutter の Windows 版(`flutter build windows`)でも使えます(PC の Celestial に自動でつながります)。

- 画面の作りは、GPU や画面の状態に左右されない試験用の描画でも確かめています([desktop_render_test.dart](app/test/desktop_render_test.dart)、結果の画像は [desktop_chat.png](app/test/goldens/desktop_chat.png))。
- 実際の窓でも、会話を開く・日本語を入力して送る・回答が流れて表示される・題名が自動で付く・Excel で保存する、までを確かめました。

```bash
cd app
```

```bash
flutter build apk --release --split-per-abi --target-platform android-arm64
```

できたら、PC から配れる場所に置きます(`~/.celestial/app/celestial.apk` に、版を書き添えて置かれます)。

```bash
celestial publish-app
```

PC の「スマホ連携」のページからダウンロードでき、入れたあとのスマホでは「設定 → このアプリについて → 更新する」で新しい版に入れ替えられます(`--split-per-abi` を付けると、ほかの CPU 向けの部品が入らず小さくなります。「見る」の文字認識などの部品を含むため、約 96MB です)。

アプリの自動テスト(繰り返しの打ち切り、拡大したままの操作の位置、PC 版の画面の描画、会話の並び順、表の表示、保存するファイルの名前)は `flutter test` で実行できます。

## 制限

- 小さなローカルのAIなので、知識や推論は大きなクラウドのAIに及びません。答え直しと裏付けで誤りを減らしていますが、誤答はあり得ます。
- 事実の裏付けは Wikipedia の利用回数の制限に当たると、しばらく行いません(そのあいだは裏付けなしで答えます)。
- PC 操作の道具と遠隔操作は Windows 向けです。
- Flutter の Windows 版は、会話と設定だけです(学習状況・精度の計測・スマホ連携などは Celestial.cmd の画面で行います)。
- 自作AIの Ollama への書き出しは Qwen2 / Qwen2.5 系の基礎モデルに限ります。
- Office のファイルは、Word・PowerPoint も既存ファイルへの末尾追記(`append`)に対応し、PDF のテキスト抽出(`read_pdf_text`)にも対応しました(部分の書き換えは Excel 中心で、複雑なグラフ・埋め込み画像の編集は扱いません)。
- スマホの中のAIだけで話した会話は、題名の自動付与の対象外です(依頼の最初の行が題名になります)。
- 事実の裏付けは、Wikipedia の検索で答えの載った項目が見つからない質問(「人口が一番多い都道府県」など)は直せません。
- 会話の記憶は「覚えて: 〜」「〜と覚えておいて」「これから〜と記憶して」「〜を忘却して」のような自然な日本語表現やエージェントの `save_memory` で扱えます(「これを覚えて」のように会話の流れが必要な指示は、通常の依頼として扱います)。
- 「覚えますか」の見分けは取りこぼしがあります(確認した8件では、本人の話の5件中2件を見逃しました)。
- プロジェクトの作成は、小さいローカルのAIで作れる規模(数ファイル)向けです。テストの実行は「コマンドと Python の実行を許可」したときだけ行います。
- 音声入力・音声会話は、端末の音声認識サービスが必要です(エミュレータでは音声が入らないため、聞き取りそのものは実機で確かめる必要があります)。
- GPU を使う処理(学習・自習・計測)を同時に重ねると、メモリ不足で失敗することがあります。
- ページの JavaScript を動かす確かめは、本物のブラウザーではありません(node と、要素・fetch・タイマーの代わりのもの)。見た目(CSS・配置・文字の大きさ)は確かめず、要素は id・class・タグの形の選び方だけを探します。外のサイトの JavaScript(CDN のライブラリなど)は動かさず、そのページでは定義されていない名前を誤りとしません。node が無い PC では行いません。
